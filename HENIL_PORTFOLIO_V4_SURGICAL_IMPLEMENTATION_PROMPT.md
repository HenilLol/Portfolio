# HENIL PATEL PORTFOLIO — V4 SURGICAL EXPERIENCE TRANSFORMATION
## Credit-Safe Implementation Prompt — Proof the Experience Before Expanding It

### 0. EXECUTIVE DIRECTIVE

This is NOT another request to "make the portfolio crazier."

Two previous large redesign passes substantially changed the code but did NOT produce the intended visual/experiential jump. Do not repeat that pattern.

The current portfolio is polished, technically substantial, and visually coherent, but it still behaves like a conventional portfolio with:
- a hero
- sections
- content blocks
- project presentations
- decorative WebGL
- HUD labels
- scroll-triggered animations

The target is fundamentally different:

> THE WEBSITE ITSELF MUST BECOME THE INTERACTIVE EXPERIENCE.

The visitor should feel that they are entering and navigating a digital environment, not scrolling through a decorated portfolio.

This prompt is intentionally designed to protect development credits:
1. Inspect the current implementation.
2. Build ONE high-fidelity vertical proof of the new interaction model.
3. Do NOT refactor the entire site yet.
4. Run the proof locally.
5. Self-audit it against the acceptance criteria below.
6. Only if the implementation genuinely changes the interaction model should you continue to integrate the same architecture into the rest of the site.
7. Do not spend time adding decorative effects that do not change the visitor's experience.

Do not create another specification document.
Do not ask for another "make it impressive" interpretation.
Use the instructions below literally.

# 1. CURRENT PROBLEM

The existing site has strong ingredients:

- Three.js / React Three Fiber
- GSAP / ScrollTrigger
- Motion
- Lenis
- Supabase CMS
- strong dark editorial visual language
- good typography

- HENEOXY architecture
- custom cursor

But the experience still reads as:

SECTION → ANIMATION → SECTION → ANIMATION → SECTION.

Scroll should not merely reveal content.
Pointer movement should not merely move a decorative light.
WebGL should not merely sit behind HTML.

The environment itself should be the interface.

# 11. THE MOST IMPORTANT TECHNICAL CHANGE

The experience should have a SINGLE WORLD STATE.

Do not build separate unrelated animations for each section.

Create an experience state model such as:

type ExperienceState =
  | "DORMANT"
  | "IDENTITY"
  | "IDENTITY_BREAK"
  | "CONSTELLATION"
  | "TECH_NETWORK"
  | "HENEOXY_ENTRY"
  | "HENEOXY";

And a continuous progress value.

Example conceptual model:

worldProgress = 0 → 1

with sub-ranges:

0.00–0.10 dormant
0.10–0.35 identity construction
0.35–0.50 identity fragmentation
0.50–0.70 constellation
0.70–0.88 technology network
0.88–1.00 HENEOXY emergence

Do NOT expose these as UI labels.

The important point is:

ONE WORLD STATE.

Not independent section animations.

# 12. WEBGL ARCHITECTURE

Use WebGL where it creates actual experiential value.

Potential primitives:
- BufferGeometry
- Points
- Lines
- InstancedMesh
- custom ShaderMaterial
- render targets only if necessary
- displacement shaders
- depth-based effects
- procedural geometry

Avoid expensive effects unless they visibly improve the experience.

The canvas should be persistent where appropriate.

Do not repeatedly mount/unmount the main world.

Do not create multiple competing RAF loops.

Use one authoritative render/update path.

Use GSAP for choreography.
Use React state only for meaningful state changes.
Avoid React re-renders every frame.

# 20. PERFORMANCE RULES

Do not sacrifice performance for spectacle.

Use:
- GPU transforms
- procedural geometry
- shader effects
- instancing
- capped DPR
- lazy loading where appropriate
- reduced geometry on mobile
- reduced effects under reduced-motion
- IntersectionObserver only for non-WebGL content activation
- one main animation/update loop

Avoid:
- hundreds of React components updating every frame
- DOM layout reads/writes every frame
- unnecessary blur filters
- giant texture downloads
- multiple canvases doing the same job
- uncontrolled particle counts

Do not write claims such as:
"60 FPS guaranteed"
"zero jank"
"sub-16ms"
unless actually measured.

---

# 21. MOBILE

Do NOT simply stack the desktop experience.

On mobile:
- touch drag controls spatial movement
- swipe can scrub transitions
- tap focuses a node
- pinch/gesture may be used only if reliable
- reduce geometry
- reduce particle count
- simplify shader complexity
- maintain the same narrative transformation

The experience should still feel designed, not merely responsive.
